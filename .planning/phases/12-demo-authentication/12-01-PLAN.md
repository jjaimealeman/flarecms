  **1a. Create `email-templates.ts`** with a `getDemoOtpEmailHtml(code: string)` function that returns `{ html: string, text: string }`. The HTML should be a professional branded email with:
  - Flare CMS branding (use inline CSS, no external assets)
  - Large, spaced-out 6-digit code display (monospace font, letter-spacing)
  - "This code expires in 5 minutes" note
  - Plain text fallback with just the code

  **1b. Add demo auth routes to `index.ts`** by creating a Hono sub-app `demoAuthAPI` and registering it via `builder.addRoute('/demo/auth', demoAuthAPI, { requiresAuth: false, priority: 100 })`.

  The sub-app has two routes:

  **POST /request** — accepts `{ email: string }`, validates with zod:
  1. Normalize email to lowercase, trim
  2. Check for existing admin session: decode `auth_token` cookie via `AuthManager.verifyToken()`. If valid and `role === 'admin'`, return 409 `{ error: "You're already logged in as an admin. Log out first." }`
  3. Block disposable domains: check `email.split('@')[1]` against a static `DISPOSABLE_DOMAINS` Set (~20 domains: mailinator.com, guerrillamail.com, tempmail.com, throwaway.email, yopmail.com, sharklasers.com, guerrillamailblock.com, grr.la, guerrillamail.info, guerrillamail.biz, guerrillamail.de, guerrillamail.net, guerrillamail.org, spam4.me, trashmail.com, trashmail.me, trashmail.net, dispostable.com, maildrop.cc, mailnull.com, spamgourmet.com, 10minutemail.com, temp-mail.org). Return 422 `{ error: "Please use a real email address." }` if blocked.
  4. Rate limit via `otpService.checkRateLimit(email, DEMO_OTP_SETTINGS)` — return 429 if exceeded
  5. Create OTP code via `otpService.createOTPCode(email, DEMO_OTP_SETTINGS, ipAddress)`
  6. Load email plugin settings from DB (`SELECT settings FROM plugins WHERE id = 'email'`), parse JSON, send via Resend API fetch (same pattern as otp-login-plugin/index.ts L162-193). Use the branded template from `getDemoOtpEmailHtml()`.
  7. Return 200 `{ message: "Check your email for a login code.", expiresIn: 300 }`

  Use these OTP settings (tighter than default plugin):
  ```typescript
  const DEMO_OTP_SETTINGS = {
    codeLength: 6,
    codeExpiryMinutes: 5,
    maxAttempts: 3,
    rateLimitPerHour: 3,
    allowNewUserRegistration: true
  }
  ```

  **POST /verify** — accepts `{ email: string, code: string }`, validates with zod:
  1. Normalize email
  2. Verify code via `otpService.verifyCode(email, code, DEMO_OTP_SETTINGS)`. On failure, call `otpService.incrementAttempts(email, code)` and return 401 with error and attemptsRemaining.
  3. Call `createDemoUser(db, kv, email, ipAddress, userAgent, jwtSecret)` to create/retrieve demo user
  4. Query the user record for id, email, role: `SELECT id, email, role FROM users WHERE email = ?`
  5. Issue a 30-minute JWT using `sign()` from `hono/jwt` directly (NOT `AuthManager.generateToken()` which hardcodes 24h):
     ```typescript
     const nowSeconds = Math.floor(Date.now() / 1000)
     const expiresAt = nowSeconds + 1800
     const demoToken = await sign(
       { userId: user.id, email: user.email, role: user.role, exp: expiresAt, iat: nowSeconds },
       c.env.JWT_SECRET || JWT_SECRET_FALLBACK,
       'HS256'
     )
     ```
  6. Set `auth_token` cookie with `maxAge: 1800` (must match JWT exp), httpOnly: true, secure: true, sameSite: 'Strict', path: '/'
  7. Set CSRF cookie: import `generateCsrfToken` from `../../../middleware` (it's already exported from middleware/index.ts). Replicate the `setCsrfCookie` pattern from routes/auth.ts L19-30 inline — generate token via `generateCsrfToken(secret)`, set `csrf_token` cookie with httpOnly: false, sameSite: 'Strict', path: '/', maxAge: 1800. NOTE: use maxAge 1800 for demo (not 86400 like the regular auth flow).
  8. Return 200 `{ success: true, isNew, expiresAt: expiresAt * 1000, redirect: '/admin' }`

  **Important implementation notes:**
  - Import `OTPService` from `../otp-login-plugin/otp-service`
  - Import `createDemoUser` from `./demo-service`
  - Import `sign` from `hono/jwt`
  - Import `getCookie, setCookie` from `hono/cookie`
  - Import `AuthManager` and `generateCsrfToken` from `../../../middleware`
  - Import `z` from `zod`
  - Define `JWT_SECRET_FALLBACK = 'your-super-secret-jwt-key-change-in-production'` (same as auth.ts)
  - Wrap each handler in try/catch, return 500 on unexpected errors with generic message
  - Use `c.req.header('cf-connecting-ip') || 'unknown'` for IP address
  - The plugin currently exports both `createDemoSandboxPlugin()` and `demoSandboxPlugin` singleton. The routes must be added inside the factory function before `builder.build()`.
