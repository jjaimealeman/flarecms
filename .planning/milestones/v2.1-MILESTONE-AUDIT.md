## Tech Debt

### 1. Dead token generation in createDemoUser

**File:** `packages/core/src/plugins/core-plugins/demo-sandbox/demo-service.ts` lines 50-55, 112
**Issue:** `createDemoUser` calls `AuthManager.generateToken` and returns `{ token, isNew }`, but the `/verify` caller only destructures `isNew`. The 24-hour token is generated and discarded every time. Wasted CPU.
**Fix:** Remove `token` from return type, drop `generateToken` calls. Caller only needs `isNew`.

### 2. Dead cookies in /verify response

**File:** `packages/core/src/plugins/core-plugins/demo-sandbox/index.ts` lines 295-312
**Issue:** `/verify` sets `auth_token` and `csrf_token` cookies with `SameSite=Strict`, but in production the request originates from `flarecms.dev` hitting `admin.flarecms.dev` — browser silently drops cross-origin Strict cookies. The `/exchange` endpoint (same-origin) is what actually sets working cookies.
**Fix:** Either add a comment documenting this is local-dev-only, or remove the setCookie calls from `/verify` entirely.

### 3. Hardcoded CORS origins in demo plugin

**File:** `packages/core/src/plugins/core-plugins/demo-sandbox/index.ts` line 111
**Issue:** Plugin CORS hardcodes `['http://localhost:4321', 'https://flarecms.dev']`. Missing `https://flare-site.pages.dev` staging origin. Other API routes read `CORS_ORIGINS` from env dynamically.
**Fix:** Read from `c.env.CORS_ORIGINS` like the rest of the app, or add the staging origin.

### Total: 3 items across 2 phases
