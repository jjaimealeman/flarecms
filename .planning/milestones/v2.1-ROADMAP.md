# Milestone v2.1: Live Demo

**Status:** SHIPPED 2026-03-18
**Phases:** 11-14
**Total Plans:** 7

## Overview

Let visitors experience FlareCMS firsthand -- email in, demo out. A public /demo page gates access via OTP email, drops visitors into the admin with a sandboxed collection they can freely edit, and a cron resets everything every 6 hours.

## Phases

### Phase 11: Sandbox Foundation

**Goal**: Demo visitors land in an admin that gives them a safe playground -- one collection they own, everything else read-only, with guardrails against abuse
**Depends on**: Nothing (builds on existing RBAC shipped in v2.0)
**Requirements**: SAND-01, SAND-02, SAND-03, SAND-04, SAND-05, DEMO-04
**Plans**: 3 plans

Plans:
- [x] 11-01-PLAN.md -- Demo sandbox plugin, migration 038, collection + demo-service, plugin registration
- [x] 11-02-PLAN.md -- Mutation rate limiting, upload restrictions middleware
- [x] 11-03-PLAN.md -- Gap closure: grant viewer on all collections for demo users (SAND-02)

**Success Criteria:**
1. demo-sandbox collection exists with title, content, and status fields pre-populated with sample rows
2. Demo user can view all collections but can only create/edit/delete in demo-sandbox
3. Demo user exceeding 50 mutations receives 429 "limit reached" response
4. Demo file uploads accept only images under 2MB
5. Every demo signup recorded in demo_signups table

### Phase 12: Demo Authentication

**Goal**: A visitor can go from entering their email to sitting in the admin dashboard in under 60 seconds, with no password to remember
**Depends on**: Phase 11 (demo role must exist for session assignment)
**Requirements**: DEMO-01, DEMO-02, DEMO-03
**Plans**: 1 plan

Plans:
- [x] 12-01-PLAN.md -- OTP send/verify endpoints, branded email template, 30-min JWT session, route wiring

**Success Criteria:**
1. Visitor submits email and receives OTP code via Resend within seconds
2. Visitor enters OTP code and is logged into admin with demo role
3. Demo session expires after 30 minutes

### Phase 13: Demo Page

**Goal**: Visitors on flarecms.dev see a clear path to try the CMS -- one page, minimal friction, straight into the admin
**Depends on**: Phase 12 (OTP flow must work before the page can use it)
**Requirements**: PAGE-01, PAGE-02, PAGE-03
**Plans**: 2 plans

Plans:
- [x] 13-01-PLAN.md -- Backend: CORS on demo auth routes, token in verify response, exchange endpoint
- [x] 13-02-PLAN.md -- Astro /demo page with audience toggle, email/OTP flow, admin redirect, nav links

**Success Criteria:**
1. Visiting flarecms.dev/demo shows explanation and email input
2. Page displays disclaimer about 30-min sessions, 50-op limits, 6-hour resets
3. After OTP verify, visitor redirected to admin authenticated as demo user

### Phase 14: Reset & Cleanup

**Goal**: The demo stays clean without manual intervention -- sandbox data resets itself, expired sessions disappear, and the system stays healthy
**Depends on**: Phase 11 (sandbox content must exist to reset)
**Requirements**: RESET-01, RESET-02, RESET-03
**Plans**: 1 plan

Plans:
- [x] 14-01-PLAN.md -- DemoResetService + cron trigger wiring (sandbox reset + user purge)

**Success Criteria:**
1. Cloudflare cron trigger fires every 6 hours automatically
2. After cron, all demo-sandbox content replaced with fresh seed data
3. After cron, all expired demo sessions purged from database

## Milestone Summary

**Key Decisions:**
- Minimal gate for demo (not polished landing) -- get people into admin fast
- Demo as plugin (not core) -- not every install needs a public demo
- 30-min JWT via direct sign() not AuthManager.generateToken() (hardcodes 24h)
- Cross-domain cookie handoff via token-in-URL exchange (SameSite=Strict workaround)
- KV key existence for demo user detection (not role check) -- avoids false-positives
- CSRF exempted for /demo/auth (unauthenticated POST flow needs it)

**Issues Resolved:**
- SameSite=Strict cross-domain cookies solved via /exchange endpoint pattern
- formData double-consumption in Hono solved via parsedFormData context variable
- Migration directory confusion solved (packages/core/migrations/, not src/db/migrations/)

**Issues Deferred:**
- None -- all 15 requirements shipped

**Technical Debt Incurred:**
- createDemoUser generates unused 24h JWT token (wasted CPU) -- remove token from return type
- /verify sets cookies that browsers silently drop in cross-origin production -- dead code
- Demo plugin CORS hardcodes origins instead of reading CORS_ORIGINS from env
