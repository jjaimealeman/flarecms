  <name>Task 1: Mutation counter and upload guard middleware</name>
  <files>
    packages/core/src/plugins/core-plugins/demo-sandbox/middleware.ts

  <action>
    Create `packages/core/src/plugins/core-plugins/demo-sandbox/middleware.ts` with two middleware functions:

    **1. `demoMutationGuard` middleware:**
    - Get user from `c.get('user')` — if no user or `user.role !== 'viewer'`, call `next()` (skip for non-demo users)
    - Check `c.req.method` — only count POST, PUT, PATCH, DELETE. Skip GET/HEAD/OPTIONS via `next()`
    - Get KV from `c.env.CACHE_KV` — if no KV, gracefully call `next()` (degrade, don't crash)
    - Read counter from KV key `demo-mutations:{user.userId}` (check the actual user ID field name — it may be `user.id` or `user.userId` depending on how auth middleware sets it; inspect `packages/core/src/middleware/auth.ts` for the exact variable name set via `c.set('user', ...)`)
    - If count >= 50, return `c.json({ error: 'You have reached the demo limit of 50 changes. Start a new demo session to continue.' }, 429)`
    - Otherwise, increment: `kv.put(key, String(count + 1), { expirationTtl: 86400 })`
    - Set response header `X-Demo-Mutations-Remaining: {49 - count}`
    - Call `next()`

    **2. `demoUploadGuard` middleware:**
    - Get user from `c.get('user')` — if no user or `user.role !== 'viewer'`, call `next()`
    - Only apply to POST requests (uploads). If method !== 'POST', call `next()`
    - Parse formData: `const formData = await c.req.formData()`
    - Get file: `const file = formData.get('file') as File | null`
    - If no file, call `next()` (let downstream handle the error)
    - Check `file.type.startsWith('image/')` — if not, return `c.json({ error: 'Demo accounts can only upload images.' }, 400)`
    - Check `file.size > 2 * 1024 * 1024` — if over, return `c.json({ error: 'Demo image uploads are limited to 2 MB.' }, 400)`
    - **Critical Hono caveat:** `c.req.formData()` consumes the request body. The downstream `api-media.ts` route also calls `c.req.formData()`. To avoid the double-consumption issue, store the parsed formData on the context: `c.set('parsedFormData', formData)`. This requires updating api-media.ts in Task 2.
    - Call `next()`

    Import types from Hono: `Context`, `Next`. Import Bindings/Variables types from `../../../app`.
  </action>
  <verify>
    - `pnpm build` succeeds
    - Both `demoMutationGuard` and `demoUploadGuard` are exported
  </verify>
  <done>
    - Mutation guard checks KV counter and returns 429 at limit
    - Upload guard validates image type and 2MB size for viewer users
    - Both middleware skip non-viewer users entirely
    - parsedFormData stored on context for downstream consumption
  </done>

    Check how existing middleware (like `requireAuth`, `csrfProtection`) is applied in app.ts and follow the same pattern. The middleware must run AFTER `requireAuth` (needs user on context) and BEFORE the route handlers.
