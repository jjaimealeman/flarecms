<task type="auto">
  <name>Task 1: Create the /demo page</name>
  <files>packages/site/src/pages/demo.astro</files>
  <action>
Create `packages/site/src/pages/demo.astro` using the site's `Layout.astro` component. The page should be a self-contained Astro page with all JS inlined via `<script is:inline>`. Use the existing design system (Outfit font, flare-500 orange, surface-* tokens, text-* tokens, border-border).

**CMS URL:** Use `import.meta.env.PUBLIC_FLARE_API_URL || 'http://localhost:8787'` in the frontmatter. Pass it to the inline script via Astro's `define:vars`.

**Page structure (top to bottom):**

1. **Hero section** — Centered layout, max-w-2xl, generous top padding (pt-24 pb-16).

2. **Audience toggle** — Pill-style toggle with two options: "For Developers" and "For Clients". Defaults to "For Developers" selected. Use `data-audience="dev"` and `data-audience="client"` attributes on content blocks. Selected pill gets `bg-flare-500 text-white`, unselected gets `bg-surface-tertiary text-text-secondary`. The toggle is a `<div>` with two `<button>` elements inside a rounded container with `bg-surface-secondary border border-border`.

3. **Headline + subtitle** — Two sets (dev and client), toggled by `hidden` class.
   - Developer: Headline "Take Flare CMS for a spin", Subtitle "See what a Cloudflare-native headless CMS can do. Full admin access, real data, zero setup."
   - Client: Headline "See your content workflow in action", Subtitle "Experience how easy it is to manage content. Edit, preview, publish -- all from one dashboard."

4. **Bullet points** — 3-4 per audience, displayed as a grid (2 cols on sm+, 1 on mobile). Each bullet is a small card with an icon (use simple SVG inline icons -- checkmark circle or similar), title, and one-line description. Use `bg-surface-secondary border border-border rounded-xl p-4`.
   - Developer bullets:
     - "Cloudflare-native stack" / "Workers, D1, R2, KV -- runs at the edge"
     - "REST API + Astro integration" / "Content Layer Loader with full type safety"
     - "Schema Migrations UI" / "Add and edit fields visually with history and rollback"
     - "Open source" / "Fork it, deploy to your own Cloudflare account"
   - Client bullets:
     - "Visual content editor" / "Rich text, media uploads, intuitive admin panel"
     - "Workflow & approvals" / "Draft, Review, Published -- content governance built in"
     - "Live preview" / "Split-screen draft preview before publishing"
     - "No setup required" / "Just log in and start managing content"

5. **Disclaimer callout** — Above the email form. Styled as a subtle info box: `bg-cyan-500/5 border border-cyan-500/20 rounded-xl p-4` with a small info icon (SVG circle-i). Text varies by toggle:
   - Developer: "Demo sessions last 30 minutes with a limit of 50 API operations. Sandbox data resets every 6 hours."
   - Client: "Demo sessions last 30 minutes with a limit of 50 content edits. Sandbox data resets every 6 hours."

6. **Email form** — Single email input with submit button. Input: `bg-surface-secondary border border-border rounded-lg px-4 py-3 text-text-primary`. Button: `bg-flare-500 hover:bg-flare-400 text-white rounded-lg px-6 py-3 font-semibold`. Stack vertically on mobile, inline on sm+. Show loading spinner on button during request. Show error messages below the form in `text-red-400`.

7. **OTP entry** (hidden initially, shown after email submission) — Swap the email form with OTP UI using DOM manipulation (add `hidden` to email form container, remove `hidden` from OTP container).
   - Six individual `<input>` elements: `type="text"`, `inputmode="numeric"`, `maxlength="1"`, `pattern="[0-9]"`. Each is `w-12 h-14 text-center text-2xl font-mono bg-surface-secondary border border-border rounded-lg focus:border-flare-500 focus:ring-1 focus:ring-flare-500 outline-none`. Arranged in a flex row with `gap-3`.
   - Auto-advance: on `input` event, if value is a digit, focus next input. On `keydown` backspace with empty value, focus previous input.
   - Paste support: on `paste` event on any input, prevent default, split the pasted text into chars, fill all 6 boxes, focus the last filled box.
   - Auto-submit: when all 6 digits are filled (after input or paste), automatically call the verify endpoint.
   - Show "Entered email" above the inputs with a "Change" link that swaps back to email form.
   - Resend link below: "Didn't get the code? Resend" -- disabled for 60 seconds after send, showing countdown. Clicking resend calls /demo/auth/request again.
   - Error display: show error text below the OTP inputs in `text-red-400`. If `attemptsRemaining` is in the response, show "X attempts remaining".

8. **Success state** (hidden initially, shown after OTP verification) — Replace OTP UI with success state. Show a checkmark SVG (green circle with white check) and "Redirecting to admin..." text. After 1.5 seconds, redirect via `window.location.href` to `{CMS_URL}/demo/auth/exchange?token={token}` where `token` is from the verify response.

**JS logic (all in a single `<script is:inline>` block with `define:vars={{ cmsUrl }}`):**

- Toggle handler: buttons with `data-toggle="dev"` and `data-toggle="client"`. On click, toggle `hidden` class on all `[data-audience]` elements matching the selected value.
- Email submit: `fetch(cmsUrl + '/demo/auth/request', { method: 'POST', headers: { 'Content-Type': 'application/json' }, credentials: 'include', body: JSON.stringify({ email }) })`. On success, swap to OTP UI, store email in a variable. On error, show error message.
- OTP verify: `fetch(cmsUrl + '/demo/auth/verify', { method: 'POST', headers: { 'Content-Type': 'application/json' }, credentials: 'include', body: JSON.stringify({ email, code }) })`. On success (`response.ok`), show success state, then redirect to `cmsUrl + '/demo/auth/exchange?token=' + data.token`. On error, show error.
- Resend: same as email submit, reset OTP inputs, restart 60s countdown.

**Important details:**
- Use `classList.add` and `classList.remove` with single class arguments (not space-separated)
- All fetch calls must include `credentials: 'include'` for cookie handling
- The page title should be "Try the Demo - Flare CMS"
- Add Plausible events: `plausible('Demo: Email Submit')` on email form submit, `plausible('Demo: OTP Verified')` on successful verify
- Support both dark and light themes (use the existing design tokens, they auto-switch)
