  <name>Task 1: Add CORS middleware, token in verify response, and exchange endpoint</name>
  <files>packages/core/src/plugins/core-plugins/demo-sandbox/index.ts</files>
  <action>
Three changes to the demo-sandbox plugin:

1. **Add CORS middleware to demoAuthAPI** — Import `cors` from `hono/cors` and add it as middleware on the `demoAuthAPI` Hono instance. Allow origins: `http://localhost:4321` (dev) and `https://flarecms.dev` (prod). Allow methods: `POST, GET, OPTIONS`. Allow credentials: `true`. The CORS middleware must be added BEFORE the route handlers.

2. **Add `token` to verify response** — In the `POST /verify` handler, add `token: demoToken` to the JSON response object (alongside `success`, `isNew`, `expiresAt`, `redirect`). This lets the cross-origin caller receive the JWT in the response body.

3. **Add GET /demo/auth/exchange endpoint** — New route on `demoAuthAPI`:
   - Reads `token` from query string: `c.req.query('token')`
   - Validates the JWT using `verify` from `hono/jwt` (import it) with `jwtSecret` (same `c.env.JWT_SECRET || JWT_SECRET_FALLBACK` pattern)
   - If invalid/expired: redirect to `https://flarecms.dev/demo?error=invalid_token` (use 302)
   - If valid: set `auth_token` cookie (httpOnly, secure, SameSite=Strict, path=/, maxAge=1800) and `csrf_token` cookie (httpOnly=false, secure=!isDev, SameSite=Strict, path=/, maxAge=1800) — same pattern as the verify handler
   - Generate a fresh CSRF token using `generateCsrfToken(jwtSecret)`
   - Redirect to `/admin` with 302

Import `verify` from `hono/jwt` at the top (alongside existing `sign` import). Use `import { sign, verify } from 'hono/jwt'`.

Do NOT change any existing route logic beyond adding `token: demoToken` to the verify response.
